## What to take from them, as options

- **MHGU-DE's readers as a check on ours.** Its MH4U readers for models, animations, collision and AI bytecode could be run beside `mhuc` on the same MH4U files, as a second implementation, before writing those specs. The licence allows reusing them with credit. Whether to vendor any of its code is the maintainer's call.
- **Its GU-side knowledge for the GU-to-4U direction.** Our GU assets come from MHXX on 3DS, whose formats are close to MHGU's but not the same (rule 2). MHGU-DE's `dt*` mapping gives the field correspondence; the MHXX side still has to be read from MHXX's own files.
- **MHGURecomp for GU behaviour.** Where a GU monster's behaviour has to be matched, watching it run natively in MHGURecomp can complement the MHXX reference recompile (docs/design/reference-recompiles.md). That would be Switch code, a reference for behaviour only and never a source of assets (rule 2).
